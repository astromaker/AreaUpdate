# Area 방식과 TaskExecuter 방식 비교 시나리오

## 목적과 비교 범위

큰 맵의 많은 Actor를 업데이트할 때, 개별 Actor의 메시지 처리와 Area 단위 직접
상호작용 사이의 처리량·tick 지연·병렬 확장성 차이를 확인합니다.

공통 비교 실행 파일은 `UpdateComparison.exe`입니다. `job`은 Actor별 TaskExecuter,
`area`는 실제 `Area::update()`와 반경 2의 상호작용 범위를 분리한 25개 partition을 사용합니다.
모든 비교에서 동일한 320×320 맵, Actor 배치, 연산, 주변 대상 선택, 누적 데미지를 사용합니다.

`area` 모드의 스케줄러는 tick마다 partition을 완료시키는 공통 시험용 실행기입니다.
실제 `AreaUpdateExample.exe`의 비동기 타이머·큐 회전 전체를 복제한 것이 아닙니다.
원본 Server 런타임 전체와 비교하는 것도 아닙니다. 이동·AOI 갱신·주변의 변경 중인
상태 읽기·여러 Actor의 원자적 거래는 이번 정량 비교에 포함하지 않습니다.
실제 `AreaUpdateExample.exe`는 별도 이동 통합시험으로 확인합니다.

## 실행 규칙

- `Source/AreaUpdate.sln`의 Release x64 실행 파일로 성능을 측정합니다.
- 각 조건은 방식별 3회 반복하고, 먼저 실행하는 방식을 번갈아 바꿉니다.
- 각 프로세스에서 같은 조건의 별도 World로 5 tick을 예열한 뒤 새 World를 측정합니다.
  예열·배치·주변 목록 생성·결과 검증·종료 시간은 측정 구간에서 제외합니다.
- 난수 시드는 42, 각 Actor의 기본 연산은 의존성이 있는 xorshift 반복입니다.
- 완료된 tick의 p99 처리시간과 처리량, 측정 구간의 프로세스 CPU 시간을 기록합니다.
  프로세스 private memory 최고치는 예열·준비·검증도 포함한 표본값입니다.
- 정상 종료, 동시 Actor 접근 0, Actor별 업데이트 횟수·받은 데미지 검증,
  방식 간 checksum·이벤트 수 일치가 통과 조건입니다.
- `events`는 공통 입력에서 생성되는 이벤트 수입니다. 수신 결과는 Actor별 누적 데미지로
  검증하며, 별도 네트워크 전달 성공률을 측정하는 항목은 아닙니다.
- 처리량 결과는 반복 실행의 중앙값으로 비교합니다. 표본 3회로 통계적 유의성은 주장하지 않습니다.

## 정확성·동시성

| ID | 시나리오 | 통과 기준 |
| --- | --- | --- |
| C01 | JobExecuter에 여러 생산자가 동시에 작업 등록 | 실행 누락 없이 같은 Actor 작업 직렬 처리 |
| C02 | wheel·heap 경계, 대량 만료, 큰 시간 경과 | 조기 실행·처리 한도 위반·Task 누수 없음 |
| C03 | 요청 승인 후 생산자를 정지시키고 Worker 종료 | 승인된 요청 등록 전 정리가 완료되지 않으며 최종 잔여 Task 0 |
| C04 | 한 partition의 실행을 멈춘 상태에서 다른 partition 실행 시도 | 서로 다른 partition의 callback 실행 중첩 없음 |
| C05 | 호출 Worker가 작업 등록 중이고 추가 batch가 쌓이는 경우 | 유휴 Worker가 깨어나 독립된 batch를 처리 |
| C06 | Actor 등록·탈퇴·이동과 queue 예약 | 기존 AreaTests 통과 |
| C07 | 동일 입력으로 두 방식 실행 | Actor별 검증과 checksum·이벤트 수 일치 |

테스트용 중단 지점은 AreaTests에만 컴파일합니다. 실제 실행 파일의 제출 경로에는 포함하지 않습니다.

## 정량 비교

처리량 시험은 100 tick을 대기 없이 실행합니다. `work`는 Actor당 연산 반복 수,
상호작용 수는 Actor당 tick당 시도 수입니다. 주변 Actor가 없으면 이벤트를 보내지 않습니다.

| ID | 배치 | Actor | 상호작용 | work | Worker | 주된 비교 목적 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| S01 | 전체 맵 균등 | 5,000 | 0 | 1,000 | 8 | 공간적으로 흩어진 독립 업데이트 |
| S02 | 전체 맵 균등 | 5,000 | 8 | 1,000 | 8 | 저밀도 주변 상호작용 |
| S03 | 중앙 64×64 | 5,000 | 0 | 1,000 | 8 | 밀집 배치에서 기본 예약 비용 |
| S04 | 중앙 64×64 | 5,000 | 8 | 1,000 | 8 | 중간 빈도 상호작용 |
| S05 | 중앙 64×64 | 5,000 | 32 | 1,000 | 8 | 높은 메시지 비용 |
| S06 | 하나의 Area | 2,000 | 32 | 1,000 | 8 | 한 Area 집중 시 병렬성 제한 |
| S07 | 중앙 64×64 | 5,000 | 8 | 20,000 | 1 | 무거운 연산의 확장성 기준 |
| S08 | 중앙 64×64 | 5,000 | 8 | 20,000 | 2 | Worker 2개 확장성 |
| S09 | 중앙 64×64 | 5,000 | 8 | 20,000 | 4 | Worker 4개 확장성 |
| S10 | 중앙 64×64 | 5,000 | 8 | 20,000 | 8 | Worker 8개 확장성 |
| S11 | 하나의 Area | 2,000 | 8 | 20,000 | 8 | 무거운 연산과 공간 집중의 결합 |
| S12 | 중앙 64×64 | 10,000 | 8 | 1,000 | 8 | Actor 수 증가 |
| S13 | 중앙 64×64 | 5,000 | 8 | 1,000 | 8 | 50ms 주기에서 tick 마감 초과율 |

S13은 100 tick을 50ms 간격으로 실행하고, 주기 대기를 제외한 tick 처리시간을 비교합니다.
주기 초과 시 기준 시각을 갱신하고 무제한 따라잡기를 하지 않습니다.

## 실제 런타임 통합시험

`AreaUpdateExample.exe 30 10000 2000 42`로 30초 동안 10,000개 Actor와 이동을 실행합니다.
동시 중복 업데이트·미실행 Actor·종료 후 남은 Task가 모두 0이어야 합니다.
이 결과는 C07의 공통 모델 성능비와 합치지 않고 별도로 기록합니다.
