# 성능 비교

## 측정 조건

아래는 보관된 2026-11-08 Release x64 실행 파일의 결과다. 이후 정리한 소스를 새로 측정한
결과로 해석하지 않는다. 실행 파일 해시와 상세 수치는 원래 보고서에 보존했다.

- 논리 프로세서 8개. Area와 Area(old)는 Worker 8개, Object는 타이머 8개와 Dispatcher 8개다.
- 목표 20FPS, signal 대기, 5ms × 256 타이머 휠, Task 수명 통계 활성화.
- 실행당 20초, seed 42/43 각 1회. 첫 1,000ms에 1ms 간격으로 분산 입장했다.
- Actor 추가 연산 0의 합성 부하이며 Actor 수에 비례해 맵과 이동 시도율을 늘렸다.
- FPS·CPU는 두 실행의 정상 구간 평균이다. CPU 100%는 논리 프로세서 전체 용량이다.

## 해석의 한계

이 합성 부하에서는 Area가 유리했지만 실제 전투·AI·네트워크 처리를 포함한 성능은 아니다.
동시접속자 수의 보장도 아니다. Area(old)는 최적화된 legacy이며 동결 원본 original이 아니다.
Object와는 총 스레드 수와 동기화 계약이 다르므로 동일 자원·동일 의미의 순수 알고리즘 비교가 아니다.
평균 FPS만으로 순간 지연이나 지속 과부하에서의 공평성을 보장할 수 없다.

## 재측정

솔루션을 Release x64로 빌드하고 Run-CurrentModelComparison.ps1과 Measure-RuntimeCpu.ps1의
매개변수와 메모리 상한을 확인한 뒤 실행한다. 현재 코드와 보관 바이너리의 측정은 구분한다.
해시·설정·환경·입력·원본 로그를 남기고 측정 중 빌드나 무거운 정적 검사를 병행하지 않는다.
과거 전용 바이너리를 요구하는 도구도 있으므로 [실험 목록](experiments/README.md)을 먼저 확인한다.
