# 설계 결정

현재 선택한 정책의 요약이다. 모든 부하에서 최적이라는 뜻은 아니다.
수치와 측정 당시의 구현 상태는 링크한 보고서에서 확인한다.

| 항목 | 현재 선택 | 이유와 남은 제약 |
|---|---|---|
| 공간 스케줄링 | 개선 Area는 공간 색상, 예전 Area는 radius lock | 계약 안의 근거리 상호작용 보호. 범위 밖은 별도 동기화 필요 |
| Active Area | Actor 수·pending·명시적 상태로 판단 | 빈 Area 갱신 제외. Actor가 남는 휴면 모델은 미분리 |
| 예약 | 50ms 절대 시각, 지난 tick 생략, 이동 시 예정 유지 | 드리프트와 이동에 따른 갱신 지연 방지. 경과 시간 보정은 게임 로직에서 검토 |
| 파티션 입장 | 기본 무제한, 고정·적응형도 선택 가능 | 측정 시 처리량 우선. 지속 유입 시 다른 파티션 대기 상한은 보장하지 않음 |
| 타이머 묶기 | 같은 기한의 예약을 batch화 | 기한을 반올림해 합치지 않음. 서로 다른 주기에서는 효과 감소 |
| Worker 대기 | signal 기본, 비교용 poll 유지 | 새 요청·이른 기한·종료를 알림. 외부 Ticker는 알림 지원 계약 필요 |
| Task 전달 | round-robin 재전달과 전용 ExecuteTask 유지 | Actor 직렬성과 소유권 유지. 바쁜 Worker에 배정될 가능성은 있음 |
| 진단 | Task 통계·Worker 일반 진단은 기본 ON, 상세 추적은 선택 | OFF의 미측정 값을 0으로 해석하지 않음 |

## 채택하지 않은 후보

- 오브젝트 풀, idle Worker 관리와 stealing은 현재 구현에 포함하지 않는다.
  [초기 최적화 기록](experiments/OPTIMIZATION.md)
- 1ms 타이머 휠은 기본값으로 채택하지 않고 5ms로 복원했다.
  [분해능 비교](experiments/WHEEL-RESOLUTION-RESULTS.md)
- Dispatcher 직접 실행기 큐는 높은 부하에서 개선됐지만 7만 Actor에서 회귀해 채택하지 않았다.
  Actor 타이머 묶음 제출과 Worker 연속 처리 후보도 기본 경로에는 남기지 않았다.
  [Object 추가 실험](experiments/OBJECT-NEXT-OPTIMIZATION.md)
- 기한 직전 능동 대기는 일관된 개선이 없어 실험 구현을 제거했다.
  [능동 대기 기록](experiments/ACTIVE-WAIT-RESULTS.md)

## 확장 전 확인

무제한 모드의 지속 유입 공평성, 국소 밀집과 긴 콜백의 지연, 서로 다른 Actor 주기,
보호 범위를 넘는 상호작용은 실제 요구사항으로 재검증한다. 과거 평균 FPS만으로 보장하지 않는다.

과거 보고서 안의 현재·기본값은 원칙적으로 측정 당시를 가리킨다.
채택 상태는 이 문서와 현행 Source, [실행 구조](runtime.md)를 함께 확인한다.
